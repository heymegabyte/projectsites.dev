# Backend platform — scan + recommendations

Scope: `src/routes/**` (65 route files, ~115 mounts), `libs/features/**` (89 dirs), `src/services/**` (420 files), `src/middleware/**` (18). Read-only.

## Surfaces inventory (surface — what — top rec [HIGH/MED])

- **Route mesh (`src/index.ts`, ~115 `app.route` mounts)** — Hono, order-sensitive (specific `:siteId/*` before catch-all `api`); every mount carries an inline "MUST precede" comment. Fragile to reorder. → Add a route-order assertion test that fails if a `:siteId/{sub}` mount lands after `api`. [MED]
- **Middleware stack (18 files)** — requestId → payloadLimit → securityHeaders → cors → auth → error_handler; plus `idempotency` (KV, org/IP-scoped, 24h), `rate_limit` (KV per-IP sliding window), `tracing` (OTLP/HTTP pure-fetch), `require_org`/`require_org_role`/`require_recent_auth`, `abuse`, `internal_hmac`. Thin + well-factored. → Wire `idempotency` onto all money/site-mutation POSTs (opt-in today). [HIGH]
- **Auth (`services/auth.ts` + `platform/identity.ts`)** — custom magic-link + Google OAuth + D1 sessions is the LIVE rail; Better Auth (consumer OIDC + enterprise SSO) ships DARK behind `BETTER_AUTH_*`. `auth_anomaly`/`auth_ai_risk`/`auth_magic`/`sso_session`. → Activate Better Auth behind a rollout flag; the dual-dark state is untested in prod. [MED]
- **Payments (Stripe)** — `billing.ts` (checkout/portal/entitlements), `webhooks.ts` (`verifyStripeSignature` + `webhook_events` idempotency), `wallet*` (credit wallet), `stripe_connect`, `billing_meter`/`usage_metering`, `subscription_cycle`. `payments_rail` feature unifies Stripe+Square (DARK). → Verify entitlement gate is fail-closed on transient (per memory `entitlement-check-fail-closed`); audit `active`-only vs `trialing`. [HIGH]
- **Per-site D1 data plane (`services/site_data_db.ts` + `d1_provisioner.ts`)** — `resolveSiteDataDb` reads `d1_database_id` from `site_database_allocations`, lazily provisions, denylists shared platform ids (`FORBIDDEN_DB_IDS`), executes via CF REST `/query`. Isolation is server-resolved. `siteDbApi` + `siteDataApi` + `dataResourceReset` (backup-first). Flags `per_site_data`/`data_resource_platform` (DARK). → Strong design; add a runtime test asserting a foreign `siteId` can never resolve another org's db id. [HIGH]
- **WfP dispatch (`services/wfp_dispatch.ts`)** — uploads user code to `USER_DISPATCH` namespace via CF REST; `isWfpConfigured` gates → 503 when unbound. Backs code-defined Functions (ADR-0035, replaces AI Agents). → Per-instance isolation only (per memory); document the shared-namespace exposure model in-code. [MED]
- **Feature-flags engine (`modules/feature_flags/` + `middleware/feature-evaluation.ts`)** — D1 3-table engine (68 flags in `registry.ts`) is admin SoT + governance; `FlagshipEvaluationProvider` prefers CF Flagship when `FLAGSHIP` bound, falls back to D1 (DARK until bound). `isFlagOn`/`resolveAllFlags`. Server guard returns 404 (not 403). → Provision Flagship + run `sync-flags-to-flagship.mjs` to go live. [MED]
- **Observability** — `structured_logger.ts` (Zod-validated `{traceId, requestId, tenantId}`), `tracing.ts` (OTLP/HTTP, no OTel SDK), PostHog (server + client meta-injected), Sentry (HTTP), Analytics Engine (`ANALYTICS`, gated by `ANALYTICS_INGEST_ENABLED="false"`), Tinybird (admin rollups). → Analytics Engine ingest is OFF — the CF-native metrics backend the doctrine mandates isn't writing. [HIGH]
- **Public API + MCP** — `api_tokens_admin` (`psk_live_*` org keys, SHA-256 hashed, scoped, `middleware/api-keys.ts` DARK behind `public_api`), `platform_mcp` (`/api/mcp`, flag `platform_mcp`), per-site `site_mcp_server` (token mint/tools/usage), `mcp_oauth` (11 providers + paste-key), `oauth_provider` (OAuth 2.1 AS), `openapi.ts` (Zod→OpenAPI 3.1 via zod-to-openapi + hono-openapi). → Public API + MCP are the platform's biggest untapped product surface (see below). [HIGH]
- **AI plane** — `ai_gateway.ts` (mandatory gateway), `ai_logger`, `ai_workflows`, `build_llm_credit`, `token_burn_meter` (per-tenant budget killswitch), `ai_crypto` (AES-GCM per-record IV). Well-instrumented. → Add Zod contracts on the remaining raw-AI-output consumers. [MED]
- **Feature-module layer** — 20 dirs carry a valid `feature.manifest.ts` (7 fields, `flagKey`→registry cross-check via `validate-feature-manifests.mjs`); ref impl `data_resource_registry` (deep, adapters/, reconciler, quota, r2_presign). → See drift rec below. [HIGH]

## New platform capabilities to add [prioritized]

1. **[HIGH] Public REST API v1 (promote `public_api` to beta).** `psk_live_*` keystore + OpenAPI 3.1 spec + scoped tokens already exist but ship DARK. Expose `GET/POST /api/v1/sites`, `/v1/sites/:id/deploy`, `/v1/sites/:id/db/*`, `/v1/media`, `/v1/forms/submissions` behind the token middleware. This is the "deliver websites programmatically" wedge — a website-delivery platform must have a public API.
2. **[HIGH] Per-site Functions GA + local dev.** WfP dispatch + `functions/` convention are built (ADR-0035) but need: a typed request/response contract, a `wrangler dev`-parity local runner, per-function logs/metrics surfaced in the editor, and cold-start/cost guards. Agentic backends live here.
3. **[HIGH] Platform MCP as a first-class product.** `platform_mcp` + `site_mcp_server` exist; publish a documented MCP catalog (create-site, deploy, query-db, list-media, submit-form) so external agents drive the platform. Pair with `.well-known/mcp` discovery (already emitted by `features.ts`).
4. **[MED] Outbound webhooks GA.** `outbound_webhooks` feature exists but is manifest-only (no schemas/service). Deliver signed, retried, DLQ'd events (site.published, form.submitted, deploy.completed) via svix-style delivery.
5. **[MED] Analytics/usage export API.** `analytics_exporter` + Tinybird rollups exist; expose per-org usage + pageview + conversion exports (CSV/JSON) under the public API for owner dashboards + billing transparency.
6. **[MED] Per-site KV + R2 + Vectorize data APIs (unify).** D1 (`siteDbApi`), R2 (`r2_buckets`), KV, Vectorize inspectors all exist as separate flag-gated surfaces; converge into one `/api/v1/sites/:id/resources/*` data-plane contract (the `data_resource_registry` adapter already models this).

## Security / Zod / observability / cost recs

- **[HIGH] IDOR coverage is strong — keep the gates in CI.** The `NO-GUARD` grep is a false alarm: flagged routes use `assertSiteOwnership` (aliased) or explicit `... WHERE site_id = ? AND org_id = ?`. Four dedicated gates exist (`check-idor-gates/handlers/get-read-idor/body-slug-write-idor.mjs`). BUT `.github/workflows/` contains ONLY `build-container.yml` — the IDOR + feature-architecture gates run via `npm run`/predeploy, not a visible CI job. Add a `feature-architecture.yml` + IDOR-gate GH workflow so drift blocks on push, not just locally. [HIGH]
- **[HIGH] Analytics Engine ingest is disabled** (`ANALYTICS_INGEST_ENABLED="false"`). The doctrine names Analytics Engine the default high-volume metrics backend, yet the hot path writes nothing to it. Enable + verify per-subdomain RUM/event sampling; reconcile display-vs-store per `verify-against-source-of-truth`.
- **[HIGH] Feature-module drift.** 89 feature dirs, ~20 with a valid `feature.manifest.ts`; several (`api_keys`, `audit_logs`) are handlers+README only — no manifest, no colocated `schemas.ts`. `validate-feature-manifests.mjs` only checks dirs that HAVE a manifest, so manifest-less feature dirs slip the gate. Add a "feature dir with handlers.ts MUST have feature.manifest.ts" check + backfill the missing manifests.
- **[MED] Zod boundary gaps.** 23 route files use `req.json().catch(()=>({})) as {…}` casts with no runtime validation (3 in `features.ts`; also `media.ts`, `env_vars.ts`, `ai_admin.ts`). All flag-gated/dark today, so no live exposure — but each MUST get a colocated Zod schema + `zValidator`/`safeParse` before its flag promotes to beta. Convert per-feature on promotion, never mass-retrofit blind.
- **[MED] Idempotency is opt-in only.** `middleware/idempotency` dedupes any mutation carrying `Idempotency-Key`, but nothing forces the header on money/site-mutation routes. Emit + require it on `/api/billing/*`, `/api/domains/purchase`, `/api/sites/:id/deploy`; per `fire-and-forget-charge-needs-source-idempotency-key`.
- **[MED] Cost.** 420 service files + 115 route mounts on one Worker = large bundle + cold-start surface; `token_burn_meter` + `build_llm_credit` guard AI spend well, but there's no per-route CPU/cost budget. Add `cost-estimator` on wrangler.toml + a per-tenant Analytics-Engine cost rollup once ingest is on.
- **[MED] CF-native wins available.** Flags via CF Flagship (provider built, unbound), metrics via Analytics Engine (built, off), rate-limit could move from KV counters to the CF Rate Limiting binding. All three are "flip a binding" leverage per `cloudflare-lock-in-is-leverage`.
